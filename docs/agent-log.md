# 에이전트 운영 기록

과제 기간에 에이전트에게 무엇을 맡겼고, 조사 결과로 무엇을 버렸는지 남긴다. 오류와 해결은 [troubleshooting](troubleshooting.md)에 따로 있다.

## 운영 원칙

- 구현 전에 타당성 조사를 먼저 맡긴다. 읽기 전용이고, 소량 표본으로 "되는지"만 본다.
- 조사 결과가 계획과 다르면 계획을 줄이거나 버린다. 아래 "버린 것"이 그 기록이다.
- 에이전트 보고는 확인한 것과 추정한 것을 나눠 받는다. 추정은 문서에 추정이라고 적는다.
- 외부 사이트는 robots.txt를 먼저 보고, 순서대로 천천히 요청한다. 막히면 우회하지 않고 멈춘다.
- 문서 승인 전에는 `frontend/src/`, `crawler/src/`를 고치지 않는다(훅이 막는다).

## 버린 것과 이유

| 하려던 것 | 버린 이유 | 근거 |
|---|---|---|
| 맘카페 글 분류 | 네이버 카페는 robots.txt가 전체를 금지하고 대부분 로그인이 필요하다 | 수집원 조사 |
| 네이버 지식인 수집 ("남편 코골이" 3,782건) | robots.txt가 AI 봇과 AI 목적 접근을 금지한다. 건수가 가장 많았지만 쓰지 않았다 | 수집원 조사 |
| 병원 337곳 홈페이지에서 진료시간·예약 경로 수집 | 표본 18곳 중 진료시간을 글자로 뽑을 수 있던 곳이 1곳. 의원급은 홈페이지가 없는 곳이 많다 | 보강 타당성 조사 |
| 네이버 예약·플레이스 링크 수집 | robots.txt가 전체를 금지한다. 병원명 검색 링크를 만드는 것으로 대체 | 보강 타당성 조사 |
| 정보가 비는 병원에 AI 전화로 문의 | 진료 중인 의원에 과제용 자동 전화를 거는 것은 부담을 준다 | 사용자와 논의 |
| 시·군·구별 검색 유입 페이지 | 대상이 "검색하지 않는 배우자"라 문제 정의와 맞지 않는다 | 사용자와 논의 |
| 큰 글씨 모드 토글 | 토스가 별도 시니어 화면을 철회한 사례. 기본 화면을 기준에 맞춘다 | 접근성 조사 |

## 에이전트가 틀린 것

| 무엇 | 어떻게 알았나 | 조치 |
|---|---|---|
| 82cook 수집 스크립트가 연결 거부를 차단으로 보지 않아, 거부된 연결 시도 383건이 간격 없이 나갔다 | 에이전트의 자체 보고 | 수집 중단. 이후 수집 지시에는 "연결 오류 1회면 즉시 종료"를 명시하고 실행 전 그 분기를 확인하게 했다 |
| 클리닉 조사에서 한 곳은 한도(4페이지)를 넘겨 5페이지를 열었고, 한 곳은 같은 주소를 세 번 요청했다 | 에이전트의 자체 보고 | 요청 한두 건이라 그대로 두고 조사 문서의 한계에 적었다 |
| 문구 감사가 읽은 `report.tsx`와 지금 파일이 달랐다(감사 중에 사용자가 고침) | 계획을 쓰면서 파일을 다시 읽어 발견 | 계획에 "지금 문구가 없으면 건너뛰고 보고"를 넣었다 |
| 82cook 재시도를 "몇 시간 뒤"에 하기로 해놓고 메인 세션이 시각을 확인하지 않아 26분 뒤에 보냈다 | 에이전트가 파일 시각으로 확인해 보고 | 요청 1건에서 끝났다. 이후 "시간이 지났다"는 전제는 시각을 확인하고 쓴다 |
| 확장 조사에서 승인받지 않은 호스트(opendata.hira.or.kr, robots.txt가 전체 금지)의 페이지를 1회 열었다 | 에이전트의 자체 보고 | 그 뒤 요청 없음. 그 파일은 받지 않았다 |
| 수집원 조사에서 지식인 표본을 브라우저 User-Agent로 받았다 | 에이전트의 자체 보고 | 표본 몇 건에서 그쳤고, 지식인은 수집 대상에서 뺐다 |
