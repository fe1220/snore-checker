# 검증: 40~60대 접근성과 쉬운 문구

> **목적:** 40~60대 접근성 기준과 쉬운 문구가 전 화면에 반영됐는지 A1~A15 기준으로 검증한 기록이다.
>
> **결론:** A1~A9, A14, A15는 통과했고 접근성 측정 88개가 통과했다. A12는 처음에 실패해 주요 신호 칩을 옮겨 고쳤다. A10·A11은 코드로만 통과했고 A13은 사용자 실기기 확인 대기다.

## 체크리스트

기준 문서: [ux-spec 접근성](../../ux-spec.md#접근성-4060대-기준), [테크스펙](spec.md)

### 자동 (`make fe-a11y`, 화면 11개 × 검사 6개)

- [ ] A1 보이는 글자가 모두 16px 이상이다
- [ ] A2 버튼·링크·선택지가 모두 48×48px 이상이다
- [ ] A3 터치 영역 사이가 8px 이상이다
- [ ] A4 글자 대비가 7:1 이상이다 (axe `color-contrast-enhanced`)
- [ ] A5 폭 320px에서 가로 스크롤이 없다
- [ ] A6 글자만 130%·200%로 키워도 가로 스크롤이 없고, 버튼 글자가 버튼 밖으로 나가지 않는다
- [ ] A7 `grep -rnE "text-(xs|sm)\b|truncate|line-clamp" frontend/src/app frontend/src/components/sleep frontend/src/components/clinics` 결과가 없다

### 브라우저

- [ ] A8 없는 주소(`/nope`)에서 한국어 안내와 "처음으로 가기"가 나온다
- [ ] A9 체크 시작 화면과 리포트 아래에서 개인정보처리방침으로 갈 수 있다
- [ ] A10 리포트에서 판정 단계, 주요 신호가 색 없이(흑백 스크린샷)도 구분된다
- [ ] A11 기기 설정에서 "동작 줄이기"를 켜면 문항 전환과 시트 전환 효과가 없다
- [ ] A12 폭 320·375 × 글자 100·130·200% 스크린샷에서 겹침·잘림이 없다 (`docs/work/02-a11y-copy/screenshots/`)
- [ ] A13 실제 휴대폰(안드로이드 글자 크기 "크게", 아이폰)에서 S1~S4를 끝까지 간다 (사용자가 확인)

### 문구

- [ ] A14 서비스 이름이 모든 화면에서 "코골이체커"다 (`grep -rn "코골이 진단\|코골이 체크" frontend/src` 결과 없음)
- [ ] A15 [copy-audit](../../research/copy-audit.md)의 수정 35건이 반영됐거나, 건너뛴 이유가 결과에 적혀 있다

## 결과 (10월 3일 새벽)

`verifier`, `design-reviewer`, 가상 사용자 테스트([persona-test](../03-clinic-data/persona-test.md))를 따로 돌린 뒤 고친 결과다. 마지막 `make gate`: 프론트 테스트 23, 크롤러 테스트 66, 접근성 측정 88 통과.

| 항목 | 결과 |
|---|---|
| A1~A9, A14, A15 | 통과. A15는 수정 권장 35건 모두 반영(26건은 대안 그대로, 9건은 이름을 "진단"으로 정하는 등 다르게 반영) |
| A10, A11 | 코드로는 통과. 흑백 화면, 기기의 "동작 줄이기"는 실제 기기에서 볼 것 |
| A12 | 처음엔 실패: 폭 320px·글자 200% 리포트에서 "주요 신호"가 카드 밖으로 잘렸다. 칩을 본문 아래로 옮겼고, 측정에 "잘린 글자" 검사를 넣었다(옛 배포본에서 이 검사가 실패하는 것을 확인). 스크린샷 66장을 다시 찍었다 |
| A13 | 사용자 실기기 확인 대기 |

디자인 리뷰와 가상 사용자 테스트에서 나온 것 중 기존 결정을 바꾸지 않는 것은 고쳤다(주요 신호 칩, "배우자 수면 효율" 문구, 첫 화면 처리방침 링크 위치, 지도 링크 중복, 배지 색, 검사비 문구). 결정이 필요한 것은 [persona-test](../03-clinic-data/persona-test.md#공통-문제와-처리)와 [agent-log](../../agent-log.md)에 남겼다.
