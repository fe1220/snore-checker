## 결정

리뷰 제안과 다르게 정한 것만 적는다.

- **C2 리포트 날짜: 머리말에서 날짜를 뺀다.**
  - 해시에 날짜를 넣으면 형식 버전이 바뀌어서, 이미 퍼진 광고·공유 링크가 깨진다.
  - 날짜가 없어도 리포트의 역할은 같다.
  - 화면 설계 S3 머리말도 같이 고친다.
- **A3 전체 목록: 화면 설계의 "나누지 않고 전부 보여준다"를 유지한다.**
  - 대신 카드에 `content-visibility: auto`를 줘서 화면 밖 카드의 레이아웃·그리기 비용을 줄인다.
  - "더 보기"를 넣으면 승인된 UX 결정과 충돌한다.
- **R2 학회 수집 실패: 실패를 숨기지 않고, 배지는 이전 값을 유지한다.**
  - 이전 `hospitals.json`의 `listed`와 홈페이지를 id 기준으로 이어 붙이고, 로그와 종료 코드로 실패를 알린다.
  - 병원 목록 갱신은 계속 진행한다. 배지 때문에 목록 갱신을 막지 않는다는 기존 결정을 지키기 위해서다.
- **P1 이전 대비 가드: 기준은 20%다.**
  - 이전 JSON보다 레즈메드 출처 병원이나 학회 배지 병원이 20% 넘게 줄면 저장하지 않는다.
  - 이전 파일이 없을 때(첫 실행)는 이 검사를 건너뛴다.
- **R1 하한선: 크롤러 하한을 300건으로 올린다.**
  - 크롤 워크플로우는 커밋 전에 프론트 테스트를 돌린다.
  - 그래서 프론트 계약 테스트가 배포 전 마지막 검사가 된다.
- **U1 GA 향상된 측정: 코드로 막을 수 없다.**
  - 콘솔 설정과 확인 방법을 `docs/architecture.md`에 적는다.
  - 콘솔 변경은 사용자가 한다.
- **C3 휴대폰 뒤로 가기: 다음 질문으로 넘어갈 때마다 `history.pushState`를 한다.**
  - 화면 안의 "이전 질문" 버튼도 `history.back()`을 써서 두 경로가 같은 동작을 하게 한다.
  - 주소는 바꾸지 않는다. 답은 계속 화면 상태에만 둔다.

- **P2 매주 커밋: 그대로 둔다.** 화면의 수집 시각을 갱신하려는 의도한 동작이라 [아키텍처](../../architecture.md)에 결정돼 있다. 리뷰가 이 결정을 놓쳤다.

## 성공 기준

- 크롤러 일부가 실패해도 줄어든 데이터가 배포되지 않는다. 실패하면 이슈가 생긴다.
- 체크 흐름에서 연타와 뒤로 가기를 해도 이벤트 중복과 단계 꼬임이 없다.
- 판정 기준은 `lib`에만 정의한다.
- 버튼 크기는 cva size 두 가지로 통일한다.
- 쓰지 않는 의존성과 파일이 없다.
- `make gate`가 통과한다. 늘어난 e2e도 함께 통과한다.
